> Purpose: Define the test any older source concept, new topic, or proposed file must pass before entering the active archive.
>
> Boundary: This file governs growth. It does not import older source files, create active files, or approve edits by itself.

Use this gate before promoting any older source concept, new topic, route, method, practice, canon candidate, or public-use idea.

The active archive stays small by default.
Do not migrate files.
Migrate functions.

Use quick passes for retrieval
and reversible mechanics.
Use patient review for meaning,
placement,
consequence,
and permanent wording.
A clean first pass remains a proposal
until it has been compared with existing files
and passed this gate.

## Gate Questions

1. What reader problem does this solve?
2. Why can't Card 1 already solve it?
3. Can this become one drill, checklist, route, or field practice?
4. Does it still serve: one messy abstraction -> one clearer next action?
5. Can a reader outside the original group or moment recover the essential meaning without guessing?
6. What difference does it preserve: a changed context, boundary, consequence, or next action?
7. Will it crowd the entrance?
8. Which existing route points to it, and where should the reader go next?

If the answer is unclear, stop before editing.

## Decision Ladder

- If it solves no clear reader problem: keep as source shelf reference.
- If it repeats an existing pattern without changing judgment or action: keep it in working notes.
- If it matters but has no active job yet: add or update `stewardship/concept-register.md`.
- If it strengthens an existing file: propose a small repair only.
- If it becomes one usable drill, checklist, or field practice: propose an active workbench outline.
- If it is about teaching, publishing, workshops, public releases, civic use, classroom use, or workplace use: hold as a deployment candidate in the concept register; do not create yet.
- If it would crowd `README.md` or create a second spine: reject for now.

No file should be created from this ladder without approval after the report.

Assess support for a claim,
relevance of its source,
value of the inquiry,
and need for more archive text separately.
A decision to add no text is an editorial judgment;
it does not establish that a source or conversation lacks value.
When existing coverage is the reason for no addition,
name the reader need it meets
and point to the maintained passage.
Ask what the source challenges,
explains differently,
or reveals that the archive overlooks.

## Deployment Candidates

Deployment contexts sit outside the two-ring archive until use proves the form.

Possible deployment categories:

- teaching / publishing / workshops / public releases
- civic applications
- classroom applications
- workplace applications

No deployment file should be created until at least three real uses show a repeated need.

Deployment ideas should stay as concept-register candidates until use proves the form.

## Stop Conditions

Stop if the proposal:

- imports an older source file whole
- repeats a job Card 1 can do
- adds a concept without a reader action
- turns a source memory into an active spine
- makes `README.md` explain more before a reader can act
- creates a file because the material is interesting rather than needed
- leaves an active file without an incoming route or an onward handoff
- weakens the core promise: one messy abstraction -> one clearer next action

The gate should make growth slower, cleaner, and easier to refuse.
